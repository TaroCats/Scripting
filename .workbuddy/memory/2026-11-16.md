## MagPanel：magpie 供应商余量 + 网关小组件（新脚本）

背景：仓库里 `scripts/MagPanel/` 之前只有一个空 index.tsx 和 scaffold 的 script.json，这次按 yetone/magpie 的
HTTP API 从零实现。

### 对接的 magpie 端点（源码确认，不是猜的）
- `GET /v1/magpie/quotas/cards` → `{"data": [SubscriptionQuota]}`；卡里 `windows[].used` 是**已用百分比**，
  `resetsAt` 是 RFC3339 字符串，`text` 标记纯文本行（积分/钱包，不能当 0% 画），`unlimited`、`extra`、`balance` 同理。
- `GET /v1/magpie/limit` → `{limited, key, limit: budget.Status, limits: [...]}`；Status 有
  `tokens/tokenLimit/tokensLeft/cost/costLimit/costLeft/reset/period/spent`。
- `GET /v1/models` → `{"data": [...]}`，只用长度当"模型数"。
- 鉴权：本机回环任意 token 放行；跨机必须启用网关 key（带 `Authorization: Bearer` 与 `x-api-key`）；
  未开「Share on local network」远端 403，key 无效 401，被限额的 key 读卡返回 403 `gateway_key_held`。
- 关键事实：只有握着登录态的那台 magpie 会问厂商，这个端点读的是它缓存的读数，所以小组件不会触发上游请求。

### 结构
- `core/api.ts` 请求层 + 错误分诊（401/403/404/429 与 error.code 分别给不同文案）
- `core/panel.ts` wire → 视图模型（leftPct = 100 - used、worst、过滤/排序/截断、网关限额文本）
- `core/store.ts` 配置与快照都走 App Group 文件（沿用开门工具踩坑结论），Storage shared 只兜底
- `core/format.ts` 百分比/倒计时/1.2k/1.2M/供应商短名/窗口名中文化/配色（返回 `KeywordsColor` 字面量，
  普通 `string` 会因 ShapeStyle 联合类型报 TS2322）
- `widget.tsx` + `widgets/*`：small 3 张、medium 2×2、large 明细、锁屏矩形/圆形/单行
- `index.tsx` 配置页：地址、网关 key（SecureField）、显示项、卡数/刷新间隔、预览、当前数据核对
- `app_intents.tsx` RefreshPanelIntent

### 找到了：magpie 网页端其实提供图标（同日再追加）
用户给出 `http://100.64.64.1:3430/api/icons/4636929b8040eb80.png`，源码核对后确认：
- **3425 是网关，3430 是 `magpie web` / 桌面 App 的网页端**（`appPageDefaultPort = 3430`）。
- 网页端有 `GET /api/icons/{name}`（`internal/gui/providers.go`，`provider.IconServed`），
  `name` 就是 `card.icon` 里 `file:` 后面那串（`^[0-9a-f]{16}\.(png|jpg|gif|webp|ico|svg)$`）。
- 网页端整体在 key 后面（`web.go` 的 `webGuard`：链接里的 `?k=<MAGPIE_WEB_KEY>` 或它换来的 cookie），
  没 key 会 401。`MAGPIE_ALLOW_IPS` 还限制来源地址。
- 所以桌面 App 不跑 `magpie web` 时这条 404，只能退回首字母徽标。

实现 `core/icon_cache.ts`：
- `iconBaseOf()`：手填优先，否则网关 host + 3430（端口原样替换）。
- `cacheCardIcons()` 在 `buildSnapshot` 里跑：只处理 `file:` 图标，`GET /api/icons/<name>[?k=]` →
  `res.bytes()` → `FileManager.writeAsBytesSync` 到 App Group 的 `magpanel_icons/`，卡片记 `iconPath`。
  哈希文件名内容寻址，命中缓存就不再请求；失败静默退徽标。新增配置 `iconBaseURL` / `iconKey`。
- 渲染：`iconPath` 有值时 `.svg` 走 `SVG filePath`，位图走 `Image filePath`（顺带解决了 PNG 类图标）。
- 踩坑：`FileManager` 不是 `scripting` 的导出成员，是全局；`Image` 的网络图属性叫 `imageUrl` 不是 `url`。

### 关键坑：`?k=` 不能直接用来取图（同日再追加）
读 `web.go` 的 `webGuard` 才发现：**带正确的 `?k=<key>` 不是放行，而是 303 跳转 + `Set-Cookie`**，
fetch 跟随后落到没有 key 的地址 → 401。所以取图必须直接发 cookie：
`Cookie: magpie_web_<port>=<key>`（源码 `webGuard("magpie_web_"+port, …)`）。
已改 `icon_cache.ts`：URL 不带 `?k=`，只发 cookie；`iconCookie()` 按 iconBase 的端口拼名字。

对用户那台 magpie（100.64.64.1）实测：
- `:3425/v1/magpie/quotas/cards` → 401（网关在跑，要 key）
- `:3430/api/icons/xxx.png` → 401「sent no sign-in cookie」（magpie web 在跑）
- `Cookie: magpie_web_3430=随便` → 401 但文案变成「cookie holds another key」⇒ cookie 名正确、按值比较
- `?k=随便` → 401「this link's key is not this magpie web's」
`/api/icons/{name}` 走 `webOwnPage` 的 CrossOriginProtection：没有 `Sec-Fetch-Site`/`Origin` 的
非浏览器 GET 视为 same-origin，放行 —— 所以 RN fetch 可用。

另外 `cacheCardIcons` 现在返回 `{fetched, failed, error}`，失败写进 `snapshot.iconNote`，
App 的「当前数据」会显示「N 个图标取不到（401…）」，便于定位。

### "Trae 有 svg 但小组件不显示" —— 单色图标坑（同日再追加）
匹配没问题，是渲染：`trae.svg` 是 `fill="currentColor"` 的单色图标。SVG 视图里
`currentColor` 不跟随系统，深色桌面上就是黑底黑图，看起来像没图标。
统计：内联的 63 个里 **24 个含 currentColor**（trae openai kimi cursor grok xai qoder
moonshot anthropic ollama zed opencode cline kilo longcat zai mimo minimax? chatglm? lmstudio
mimocode gmicloud commandcode）。magpie 自己是怎么处理的：`pageIconOf` 里
`Mono: ext == ".svg" && !strings.HasSuffix(name, "-color")`，页面把单色图当遮罩用文字色填充。
修法两重保险：
1. 渲染时检测 `currentColor` → `renderingMode="template"` + `tint="label"`（模板只取 alpha，颜色跟随文字色）；
2. 同时把代码里的 `currentColor` 烤成 `#8E8E93`，万一模板模式在 widget 里不生效也看得见。
下载来的 SVG 在写盘前也做同样烘焙（`Data.fromUint8Array().toRawString()`，失败就原样写）。
缓存目录升到 `magpanel_icons_v2`，强制丢掉旧的不带烘焙的文件。
判断"单色"一律以 SVG 内容里的 `currentColor` 为准，不要靠 `-color` 后缀猜。

**修正结论（用户反馈后确认）**：`currentColor` 在这个 SVG 渲染器里不是"画成黑色"，
而是**直接画成空白**（App 列表里也是空的），`renderingMode="template"` + `tint` 同样画不出来。

**真正的根因（用"复制图标诊断"的文本验证）**：解析和取图全对（Marvis 的 PNG 已缓存 11155B，
说明 3430 + cookie 链路通），空的是 `SVG` 视图本身 —— **`resizable` 会把 SVG 画成 0 尺寸**。
时间线吻合：v1 没加 resizable 时图标能看见只是偏大；v2 加了 resizable 之后全空。
最终方案：**不用 `resizable`/`scaleToFit`**，把 `width`/`height` 直接写进 SVG 根节点
（`svgWithSize(code, size)`，把 `1em` 换成具体 pt），frame 只管布局；缓存下来的 SVG 文件
写盘时也把宽高固定成 64。判断顺序：本地文件 → 内联 SVG（带尺寸）→ GENERIC_ICON。

### 逐个图标的三种失败模式（用户按图标回报后定位）
用户回报："trae 正常 / WorkBuddy 异常 / Qoder 不显示 / Marvis 正常"，三种根因完全不同：
1. **没有 `viewBox`（WorkBuddy）**：SVG 只有 `width="64" height="64"`，我把宽高改成 11 后，
   视口缩了但内容仍按 64 单位画 → 只剩左上角一块（"异常"）。修：缺 viewBox 的按原宽高补
   `viewBox="0 0 64.0003 64"`。
2. **渐变 / clipPath 引用（WorkBuddy）**：`fill="url(#gradient_0)"`、`fill="url(#glow_0)"`、
   `clip-path="url(#clip_1)"` —— 简易光栅化器不认 → 空白或黑块。修：把 url(#…) 换成该渐变
   第一个 `stop-color`（共 17 处），`clip-path` 属性直接删（宁可形状溢出）。
3. **圆弧命令（Qoder）**：path 里 `a` 命令用了压缩 flag 写法（`0 01-.014.454`），解析器炸 → 空白。
   修：离线用 `svgpath` 把**所有** path 规范成绝对坐标 + 圆弧转贝塞尔（137 条路径改写，
   Qoder 6239B→7622B），畸形数据一律 round(2)，NaN 就保留原值。
结论：这个 SVG 光栅化器只接受"规矩"的 SVG —— 必须有 viewBox、不能用 url(#…) 引用、
path 不能有压缩写法的圆弧。以后加新图标要先过这三道。

真正的修法只有一条：**构建期把 `currentColor` 替换成具体颜色**（`#8E8E93`），
运行时不要再做模板着色。证据：`-color` 那批一直正常、单色那批一直空，正好是
"小组件只有部分有" + "Trae 那行是空的"。已核对 63 个 SVG 全部是合法 XML 且无 currentColor。
