# 2026-11-18

## Launch 小组件：高分辨率图标 + 文件夹分区 + iCloud（v1.11.0）

项目：`scripts/Launch`（启动台，Scripting App 小组件 + in-app 编辑器）

### 需求 2 的正确理解（重要，曾理解错一次）
用户要的**不是**把整个小组件排成多宫格，而是：小组件**均分成多个区域，每个区域完整展示一个文件夹**。
- `systemLarge` → 均分 2 个区域
- `systemExtraLargePortrait`（及 systemExtraLarge）→ 均分 3 个区域
- 每个区域内部**有自己独立的配置**（布局/图标大小/间距/形状/圆角/渲染模式/封面）

### 每个区域独立配置（v1.10.0 新增）
- `WidgetPanelConfig extends FolderStyle` + `folder?: string`，即每个区域复用同一套外观字段，再加一个文件夹选择。
- `Config.widgetPanels: WidgetPanelConfig[]`（3 个）。旧格式是 `string[]`，`normalizeWidgetPanels()` 负责迁移。
- **新增 `components/PanelSettings.tsx`**：单区域设置页（Form）。设置页「文件夹分区」里每行是 `NavigationLink`，显示「文件夹名 · 布局名」，点进去配置。
- 属性级联优先级（用户明确要求文件夹优先，v1.10.1 已调整）：**文件夹 style > 区域 style > 全局 config**。图标大小/间距/圆角未设置时显示“自动”，由 `min(panelWidth, contentHeight) * 0.3` 推算。
- `PanelContent` 的 layout/cover 由 `PaneledLayout` 解析后传入，不再自己读 folder.style。
- 分区**触发条件**：至少一个区域显式指定了文件夹（`divisionRequested`）。否则保持原视图——避免覆盖既有的全局 `widgetLayout` 配置。

### 1. 图标清晰度
- 根因：`SearchSheet` 的 `pickArtwork` 只用 iTunes 搜索返回的 `artworkUrl100`（100×100 缩略图），小组件放大后发虚。
- 修复：新增 `constants.ts` 的 `highResArtworkUrl()`，正则改写 Apple CDN URL 末尾尺寸段（`100x100bb.jpg` → `512x512bb.jpg`）与 `pickArtwork()`（优先 `artworkUrl512`）。
- 已验证：Apple CDN 会按请求尺寸从原图重新渲染，512×512 / 1024×1024 均为真实分辨率，非放大插值。
- `migrateAppItem()` 增加 `upgradeIconArtwork()`，自动把旧数据里的 100x100 URL 升级；缓存 key 是 URL 的 md5，改写后会重新下载。

### 2. 文件夹分区渲染
- `panelCountForFamily(Widget.family)`：systemLarge → 2，extraLarge / extraLargePortrait → 3，其余 1。**用 Widget.family，不猜尺寸**。
- `resolveWidgetPanels(folders, apps, configs, count)` → `WidgetPanel[]`（folder/apps/style）。显式优先，空位按文件夹列表顺序补，跳过已用/不存在。
- `PaneledLayout`：沿长边均分（竖版堆叠、横版并排，`panelAxisForSize`），面板间插 `Divider`；3 个区域或单区域 <150pt 进 compact 模式。
- `AutoGridLayout` 增加 `embedded`：区域内固定间距居中，不把间距拉满宽度。
- `FixedGridLayout` 的 padding/gap 改为按 `min(width,height)` 比例缩放，窄区域不被 16pt 内边距吃掉。
- 参数：`folders=A,B` / `panelAxis=columns|rows`。

### 3. 宫格能力（保留）

- `MAX_WIDGET_SLOTS` 4 → 9；文件夹级布局在「文件夹设置 → 小组件」。

### 4. iCloud 存储（v1.11.0 新增，`cloudSync.ts`）
- **架构决策**：工作副本仍在 App Group（`BASE_PATH`），iCloud 只做持久化镜像。原因：小组件扩展同步渲染、无法等待 iCloud 下载；`appGroupDocumentsDirectory` 是文档中唯一明确「widget 可访问」的目录。
- 镜像位置：`FileManager.iCloudDocumentsDirectory + '/' + Script.name`（即 iCloud Drive/Scripting/Launch）。
- `syncWithiCloud()` 启动时对账：比较 `launcher_apps.json` 的 `statSync().modificationDate`，云端更新则 pull，否则 push。
- `pushToiCloud()` 在每次保存后调用（apps/folders/config 三个 effect + `saveButtonCode`）。JSON 带 mtime 守卫跳过未变文件；buttons/cache 只补缺失文件（内容按 id 寻址）。
- 首次安装（本地空、云端有）→ pull 全量恢复，含用户自选图标（cache 里不可再生的 `img_*`）与自定义按钮代码。
- 安全：iCloud 下载用 `withTimeout` 5s 兜底；下载失败返回 `'none'` 而不是 push，避免用旧数据覆盖云端。
- `FileManager.isiCloudEnabled` 为 false 时全部 no-op（`iCloudDocumentsDirectory` 会抛错，已 try 包裹）。
- 设置页新增 iCloud Section：状态（已开启/未开启）+「立即备份」按钮。
- 测试：用内存 FileManager 桩编译 `cloudSync.ts` 跑了 7 个用例（首次推送/本地较新/云端较新/重装恢复/iCloud 关闭/buttons+cache 上传/恢复），全部 PASS。
- 坑：`FileManager.readDirectorySync` 返回**裸文件名**，不是完整路径（见 `pruneButtonCode` 的用法）。
