# 2026-11-18

## Launch 小组件：高分辨率图标 + 文件夹分区 + iCloud（v1.11.3）

项目：`scripts/Launch`（启动台，Scripting App 小组件 + in-app 编辑器）

### 需求 2 的正确理解（重要，曾理解错一次）
用户要的**不是**把整个小组件排成多宫格，而是：小组件**均分成多个区域，每个区域完整展示一个文件夹**。
- `systemLarge` → 均分 2 个区域
- `systemExtraLargePortrait`（及 systemExtraLarge）→ 均分 3 个区域
- 每个区域内部**有自己独立的配置**（布局/图标大小/间距/形状/圆角/渲染模式/封面）

### 每个区域独立配置（v1.10.0 新增）
- `WidgetPanelConfig extends FolderStyle` + `folder?: string`，即每个区域复用同一套外观字段，再加一个文件夹选择。
- `Config.widgetPanels: WidgetPanelConfig[]`（3 个）。旧格式是 `string[]`，`normalizeWidgetPanels()` 负责迁移。
- **新增 `components/PanelSettings.tsx`**：单区域设置页（Form）。设置页「文件夹分区」里每行是 `NavigationLink`，显示「文件夹名 · 布局名」，点进去配置。
- 属性级联优先级（用户明确要求文件夹优先，v1.10.1 已调整）：**文件夹 style > 区域 style > 全局 config**。图标大小/间距/圆角未设置时显示“自动”，由 `min(panelWidth, contentHeight) * 0.3` 推算。
- `PanelContent` 的 layout/cover 由 `PaneledLayout` 解析后传入，不再自己读 folder.style。
- 分区**触发条件**：至少一个区域显式指定了文件夹（`divisionRequested`）。否则保持原视图——避免覆盖既有的全局 `widgetLayout` 配置。

### 1. 图标清晰度
- 根因：`SearchSheet` 的 `pickArtwork` 只用 iTunes 搜索返回的 `artworkUrl100`（100×100 缩略图），小组件放大后发虚。
- 修复：新增 `constants.ts` 的 `highResArtworkUrl()`，正则改写 Apple CDN URL 末尾尺寸段（`100x100bb.jpg` → `512x512bb.jpg`）与 `pickArtwork()`（优先 `artworkUrl512`）。
- 已验证：Apple CDN 会按请求尺寸从原图重新渲染，512×512 / 1024×1024 均为真实分辨率，非放大插值。
- `migrateAppItem()` 增加 `upgradeIconArtwork()`，自动把旧数据里的 100x100 URL 升级；缓存 key 是 URL 的 md5，改写后会重新下载。

### 2. 文件夹分区渲染
- `panelCountForFamily(Widget.family)`：systemLarge → 2，extraLarge / extraLargePortrait → 3，其余 1。**用 Widget.family，不猜尺寸**。
- `resolveWidgetPanels(folders, apps, configs, count)` → `WidgetPanel[]`（folder/apps/style）。显式优先，空位按文件夹列表顺序补，跳过已用/不存在。
- `PaneledLayout`：沿长边均分（竖版堆叠、横版并排，`panelAxisForSize`），面板间插 `Divider`；3 个区域或单区域 <150pt 进 compact 模式。
- `AutoGridLayout` 增加 `embedded`：区域内固定间距居中，不把间距拉满宽度。
- `FixedGridLayout` 的 padding/gap 改为按 `min(width,height)` 比例缩放，窄区域不被 16pt 内边距吃掉。
- 参数：`folders=A,B` / `panelAxis=columns|rows`。

### 3. 宫格能力（保留）
- `WidgetLayout`：`auto | single | dual | triple | quad | six | nine`，`MAX_GRID_COLUMNS = 3`。
- `FixedGridLayout` 统一处理所有固定宫格（原 `DualAppLayout` / `QuadLayout` 已删）。
- `MAX_WIDGET_SLOTS` 4 → 9；文件夹级布局在「文件夹设置 → 小组件」。

### 4. iCloud 存储（v1.11.0 新增，`cloudSync.ts`）
- **架构决策**：工作副本仍在 App Group（`BASE_PATH`），iCloud 只做持久化镜像。原因：小组件扩展同步渲染、无法等待 iCloud 下载；`appGroupDocumentsDirectory` 是文档中唯一明确「widget 可访问」的目录。
- 镜像位置：`FileManager.iCloudDocumentsDirectory + '/' + Script.name`（即 iCloud Drive/Scripting/Launch）。
- `syncWithiCloud()` 启动时对账：比较 `launcher_apps.json` 的 `statSync().modificationDate`，云端更新则 pull，否则 push。
- `pushToiCloud()` 在每次保存后调用（apps/folders/config 三个 effect + `saveButtonCode`）。JSON 带 mtime 守卫跳过未变文件；buttons/cache 只补缺失文件（内容按 id 寻址）。
- 首次安装（本地空、云端有）→ pull 全量恢复，含用户自选图标（cache 里不可再生的 `img_*`）与自定义按钮代码。
- 安全：iCloud 下载用 `withTimeout` 5s 兜底；下载失败返回 `'none'` 而不是 push，避免用旧数据覆盖云端。
- `FileManager.isiCloudEnabled` 为 false 时全部 no-op（`iCloudDocumentsDirectory` 会抛错，已 try 包裹）。
- 设置页新增 iCloud Section：状态（已开启/未开启）+「立即备份」按钮。
- 测试：用内存 FileManager 桩编译 `cloudSync.ts` 跑了 7 个用例（首次推送/本地较新/云端较新/重装恢复/iCloud 关闭/buttons+cache 上传/恢复），全部 PASS。
- 坑：`FileManager.readDirectorySync` 返回**裸文件名**，不是完整路径（见 `pruneButtonCode` 的用法）。

### 5. 分区不显示文件夹名，内容铺满（v1.11.1）
- 删除 `PanelHeader` 组件，`PaneledLayout` 不再预留标题高度，`contentHeight = panelHeight`。
- 每个 panel 包一层 `frame={{ width: panelWidth, height: contentHeight }}` 的 VStack，让内部 Spacer 能真正均分（否则会塌成内容固有高度）。
- `AutoGridLayout` 增加显式 `frame={{ width, height }}`。
- **新增 `MAX_PANEL_COLUMNS = 5`**：分区内是「宽而矮」的横条，沿用全局 3 列上限会在两侧留大片空白。`AutoGridLayout` 在 `embedded` 时用 5 列上限，并把余量作为间距均分，铺满整宽。固定宫格（quad/six/nine）仍按自身行列，不受影响。
- 实测填充率：systemLarge 2 区 ≈88%，extraLargePortrait 3 区 ≈90%。

### 6. 分区之间不留间隔（v1.11.2）
- 移除 `Divider` 分隔线与面板间距：`PaneledLayout` 外层 VStack/HStack `spacing={0}`，不再有 `between` 扣减。
- 同时删掉 `Divider` 导入。仅保留最外层 `padding`（10/12pt）避免图标贴小组件边框。
- 面积利用率：systemLarge 2 区 ≈93% 宽，extraLargePortrait 3 区 ≈93%。

### 7. 分区宽高都铺满（v1.11.3）
- `PaneledLayout` 的 `padding` 改为 **0**，面板直接吃满小组件内容区。
- `AutoGridLayout` 的 `embedded` 分支重写：不再用 Spacer 居中，而是先按最小间距 `gap` 选出列数（上限 `MAX_PANEL_COLUMNS=5`）和可容纳行数，再用 `gapX=(W-cols*icon)/(cols+1)`、`gapY=(H-rows*icon)/(rows+1)` 把余量均分成间距 —— 宽高都精确 100% 填满。
- `FixedGridLayout` / `SingleAppLayout` 新增 `flush` 参数（`PanelContent` 传 true），去掉内部 16pt / 比例内边距。
- 注意：方形图标在 2×2 这类固定宫格里只能填满一个维度（另一个维度留白居中），这是几何限制；自动网格通过自适应列数可以两维都填满。

### 8. 修复：分区设置不生效（v1.11.4 之后）
- **根因**：`PanelSettingsView` 没有本地 state，完全依赖 `panel` prop 驱动 UI。但 `NavigationLink` 的 destination 在 push 时被捕获，父组件 state 变化不会更新已推入页面的 props。
  - 后果 1：步进器显示值永不变化，看起来"点了没反应"。
  - 后果 2：`onIncrement` 里 `const value = effectiveIconSize + 1` 的基值恒定，连续点 + 一直写入**同一个数**。
  - 后果 3：`update()` 里 `{ ...panel, ...patch }` 展开的是**过期快照**，改第二个字段会把第一个字段冲掉。
- **修复**：改用本地 `useState<WidgetPanelConfig>(panel)` 作为 `draft`，`update()` 基于 `draft` 展开，先 `setDraft` 再 `onChange` 持久化；重置按钮同时清空 draft。
- 经验：Scripting 中任何 `NavigationLink` 编辑页都**必须**用本地 state 驱动，参照 `FolderSettingsView` 的写法。
- 另注：级联是「文件夹 style > 区域 style > 全局」，若文件夹自身设了某项（如 iconSize），区域里对应项会被覆盖，UI 会显示「30 · 跟随文件夹」提示。

### 9. 真正的根因：固定宫格布局完全忽略 iconSize / spacing
- 上一轮修的「无本地 state」确实是个 bug，但**不是**用户看到的主因。
- 实测（用真实 `normalizeWidgetPanels` / `resolveWidgetPanels` 跑保存→落盘→重载→解析）证明**配置存取链路完全正常**，iconSize=72 / spacing=4 一路完好。
- 真正原因在渲染层：
  - `FixedGridLayout`（单/双/三/四/六/九宫格）的图标尺寸**只由单元格几何决定**，从头到尾没读过 `config.iconSize`，也没读过 `config.spacing`。
  - `SingleAppLayout` 同样用 `min(width,height)*0.44`，忽略 `config.iconSize`。
  - 自动网格的 `gap` 被 `iconSize*0.35` 封顶，且余量又被拉伸填满，所以**间距设置实际上也是死的**。
  - 结论：只要文件夹设了固定宫格布局，图标大小/间距改什么都看不出来。
- 修复：新增 `RenderConfig = Config & { iconSizeSet?, spacingSet? }`，由 `configForPanel` 标记「该项是否来自真实设置（区域或文件夹）」：
  - `FixedGridLayout`：显式 spacing 用作 gap；显式 iconSize 作为单元格尺寸的**上限**。
  - `SingleAppLayout`：显式 iconSize 直接生效。
  - 自动网格 embedded：显式值按字面使用并居中；未设置时保持铺满。
- 另一个隐患：小组件参数 `folders=a,b` 之前会**整个替换** panel 列表并丢掉 style（预览按钮生成的参数就带 `folders=`）。已改为按位合并，只覆盖文件夹、保留外观。

### 10. 新功能：区域定位（居中 / 顶部 / 底部）
- `PanelAlign = 'center' | 'top' | 'bottom'`，默认 `center`。
- 字段挂在 `FolderStyle.align`（`WidgetPanelConfig` 继承），级联同其它外观：**文件夹 align > 区域 align > center**。
- `normalizeWidgetPanels` 已保留 `align`。
- 渲染：`SingleAppLayout` / `FixedGridLayout` / `AutoGridLayout(embedded)` 都接收 `align`，用 Spacer 控制垂直落位：
  `before = align !== 'top'`，`after = align !== 'bottom'`。
  铺满模式下内容刚好填满，Spacer 为 0，所以不影响「铺满」；只有显式设置了图标大小/间距、内容没填满时才看得出效果。
- 封面模式（AppCover）铺满整块，align 不适用，保持原样。
- 设置页在「布局」下方新增「位置」Picker。

### 11. 顶部/底部定位保留 10pt 边距
- 新增常量 `ALIGN_INSET = 10`（widget.tsx）。
- `align === 'top'` → 上边距 `max(原内边距, 10)`；`align === 'bottom'` → 下边距同理；`center` 不变。
- 三个布局都做了：`SingleAppLayout` / `FixedGridLayout`（padding 改为四边对象，`cellHeight` 用 `padTop+padBottom` 计算）/ `AutoGridLayout(embedded)`（先从高度里扣掉 10 再算行数与 gapY）。
- 效果：top 时内容距顶 10pt、余量落到下方 Spacer；center 时仍然精确铺满。
