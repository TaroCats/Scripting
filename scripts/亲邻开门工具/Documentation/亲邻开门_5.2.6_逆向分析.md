## 0. 先看结构性结论（决定了后面能看到什么）

这个 APK **不能按普通 Android 应用做 Java 反编译**，原因有三层：

| 层 | 事实 | 证据 |
|---|---|---|
| dex | `classes.dex` 只声明 **3 个类**：`com.mx.shell.CoreHelper`、`MXAppComponentFactory`、`MXApplication` | 直接解析 dex class_defs |
| 加固 | 真实业务 dex 被加密，运行时由 `lib/arm64-v8a/libmxldd.so` 解密 | 清单 `application` 指向壳 Application；其余 7 个 dex 全是第三方 SDK（`a/a/a`、`a0/b`、`xg/e` 等混淆包） |
| 业务实现 | **Flutter（Dart AOT）**，逻辑编译进 `lib/arm64-v8a/libapp.so`（19.2 MB） | `libflutter.so` + `libdartjni.so` + `libiris_*` + `libapp.so`；`flutterEmbedding` meta |

**所以：** Java 层的 `com.qinlin.edoor.MainActivity`、`login.SimLoginActivity` 等类虽然写在清单里，但类体在加密 dex 中，JADX 取不到（`get_methods_of_class` 返回 not found，属实）。业务逻辑以机器码形式存在于 `libapp.so`，Dart 符号已剥离，**只有字符串表保留**。

下面所有"逻辑"都是从**接口契约 + 字符串证据**反推的，不是从控制流读出来的。这一点先讲清楚，别当成已执行的流程。

### 1.3 传输与加密
- 请求体加密：**AES/ECB/PKCS5**（`FlutterAesEcbPkcs5`、`AesHeader`、`aesEncrypt`/`aesDecrypt`/`_decodeAes`）
- 签名：**MD5**（`_md5Encrypt`、`_calculateMd5`）+ 参数 `sign`/`timestamp`/`nonce`/`appId`/`channel`
- 字符串表里有两枚 32 位十六进制常量，形态符合 AES-128 密钥或 MD5 种子：
  - `91FC5A0CA0856C01A913CD77F21066AC`
  - `FBC213C4C7BEEBD2AA4EDBF0F681C41B`
- **硬编码密钥泄漏**：`&appsecret=OKFoQ9MmNXQtcyXROo4PnaFkfDPTHuDg`（明文躺在 `libapp.so` 字符串表里，第三方 SDK 的 URL 参数）

## 2. 长期保活

### 2.1 先排除的两个常见答案
- **没有** `RECEIVE_BOOT_COMPLETED` → 不做开机自启
- **没有** `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` → 不申请电池优化白名单

也就是说，它没有走"开机拉起 + 杀不死"的那套野路子。

### 2.2 真实机制：推送通道 + 厂商系统级长连接

清单里 `service`/`receiver` 声明完整指向一套标准推送矩阵：

| 通道 | 组件 | 进程 |
|---|---|---|
| 阿里云/友盟 ACCS 长连接 | `com.taobao.accs.ChannelService`、`ChannelService$KernelService`、`com.taobao.agoo.AgooCommondReceiver`、`com.umeng.message.UmengIntentService` | `:channel` |
| 友盟通知服务 | `com.qinlin.edoor.push.umeng.UmengNotificationService` | 主进程 |
| 华为 HMS | `com.huawei.hms.support.api.push.service.HmsMsgService`、`com.qinlin.edoor.push.huawei.HuaweiMessageService` | `:pushservice` |
| 小米 | `com.xiaomi.push.service.XMPushService`、`XMJobService` | `:pushservice` |
| OPPO / vivo / 荣耀 | 权限 `com.coloros.mcs.permission.RECIEVE_MCS_MESSAGE`、`com.heytap.mcs...`、`com.vivo.notification.permission.BADGE_ICON`、`com.hihonor.permission.MANAGE_FOLD_SCREEN` | 系统通道 |

配套权限：`WAKE_LOCK`、`FOREGROUND_SERVICE`（+`DATA_SYNC`、`MEDIA_PROJECTION`，但后者属 Agora 投屏和广告下载器，不是业务保活）、`com.qinlin.edoor.permission.PROCESS_PUSH_MSG` / `PUSH_PROVIDER`。

Flutter 侧：`UmengSdk`、`wakelock_plus`（保屏幕常亮，不是进程保活）。

### 2.3 结论
- "常年在线"= **厂商推送通道（系统级，App 被杀也能收）+ 阿里 ACCS 自己的长连接**，标准 SDK 级保活。
- **没有**自研守护进程、双进程互拉、1 像素 Activity、JobScheduler 心跳这类灰色手段。
- 代价：一旦厂商通道被用户关闭（通知权限/自启动限制），没有任何兜底长连接可用 —— 因为业务侧没有独立 socket/heartbeat（Dart 侧 `heartbeat`/`websocket`/`mqtt` 全部命中为零，只有 Flutter 框架自带的 `RawSocket`/`KeepAlive` 类名）。

## 4. 安全观察（顺带）

1. **加固挡不住字符串**：DEX 加密了，但 Dart AOT 没剥字符串，41 个 `app/api/...` 接口、加密算法名、密钥常量全裸。
2. **AES-128 ECB + MD5 签名**：ECB 无 IV，弱于 CBC/GCM；MD5 已不适合做完整性校验。
3. **硬编码 `appsecret`**：`OKFoQ9MmNXQtcyXROo4PnaFkfDPTHuDg` 明文可提取。
4. **权限面很宽**：`QUERY_ALL_PACKAGES`、`RECORD_AUDIO`、`CAMERA`、精确/粗略定位、`REQUEST_INSTALL_PACKAGES`，以及百度定位 + 百度地图（`com.baidu.location.f` 独立 `:remote` 进程）。
5. **广告 SDK 密度高**：穿山甲（`com.byazt`）、快手（`com.kwad`）、优量汇/腾讯（`com.qq.e`）、tanx（阿里）、`com.yfanads`，其中 `com.yfanads` 还带独立下载器进程 `:filedownloader`、`:downloader`。
6. **样本来源 APKPure**，签名与官方包是否一致未验证（本次未做证书校验）。

## 附录 B：为什么 Ghidra 在这里给不出调用顺序（实测，不是推测）

1. **自动分析实测 1 秒结束、恢复 0 个函数。** Ghidra 的 `Disassemble Entry Points` 耗时 0.001 s —— 因为产物没有 entry point，也没有任何符号供它起步，flow-based 反汇编没有种子，整个 `.text`（11.7 MB）保持未定义状态。
2. **符号表为空**：`nm libapp.so` → `no symbols`；`.dynsym` 只有 5 个导出（`_kDartVmSnapshotData`、`_kDartIsolateSnapshotData`、`_kDartVmSnapshotInstructions`、`_kDartIsolateSnapshotInstructions`、`_kDartSnapshotBuildId`）。
3. **快照被明确裁掉调试信息**。VM 快照头 feature 串：
   `product no-code_comments no-dwarf_stack_traces_mode dedup_instructions no-tsan no-msan no-shared_data arm64 android compressed-pointers`
   - `product`：release，无断言/无调试
   - `no-code_comments`：**没有 offset→函数名 的映射表**（这正是产物里 `_onScanOpenDoor` 这类字符串只是普通字符串常量、而非符号的原因）
   - `no-dwarf_stack_traces_mode`：没有 DWARF
4. **字符串无法 xref**：`compressed-pointers` + `no-shared_data` 让对象引用变成相对快照基址的 32 位偏移。实测在 7.2 MB 的 isolate 快照数据里，指向字符串对象的绝对指针数量为 0（全库只有 520 个自引用指针，无一落在目标字符串附近）。Ghidra 因此无法把 `"openDoorByMethod"` 这类字符串反向关联到引用它的代码。

**结论**：对这个特定产物，"装个 Ghidra 点一下" 拿不到登录/开门的调用链。要拿到函数名，只能靠能反序列化 Dart 快照自身元数据的工具（Blutter 这一类），它不走符号表，而是重建对象图。
