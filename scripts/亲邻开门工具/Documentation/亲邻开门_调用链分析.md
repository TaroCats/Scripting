## 一、登录

### 1.1 验证码发送（分支最清楚的一段）

入口 `_LoginPageState::buildBtn` @`0xbb0410`（Dart 源码 `pages/login/login_page.dart`）

```
按钮文案 = "获取验证码"                          // [pp+0x56878]
onClick →
  FocusScope.of → FocusNode.unfocus             // 先收键盘
  cmp w3, #0x16 (Smi 22 → 11 位)                // 手机号长度检查
    ├─ 不满足 → MsgUtil.toast("请输入11位的手机号")   // [pp+0x56cc0]
    └─ 满足   → _LoginPageState::getValidCode @0xbb0700
                  Map{"mobile": <手机号>}        // [pp+0x3570] "mobile"
                  → Interface::interfaceSendValidCode
                  → setState
```

**条件分支证据**：`cmp x3, #0x16` 后接 `b.eq`。`0x16` = 22 = Dart Smi 编码的 11（`11 << 1`），与 toast 文案"请输入11位的手机号"完全对应。

### 1.2 验证码校验回调

闭包 @`0xbd793c`：

```
取 map["code"]                                   // [pp+0x5a08] "code"
  ├─ 值为 null / 类型不符（tbz w0,#0 / tbz w0,#4）
  │    → MsgUtil.toast("验证码有误，请重新输入")   // [pp+0x56f48]
  │    → Future.delayed(...)                     // 延时后清空/重试
  └─ 通过 → 提交登录
```

同一文件另有闭包 @`0x8f3088` 携带规则文案："1.每天最多获取5次验证码\n2.每个验证码发送后5分钟内有效" —— 服务端限流策略在客户端也有提示副本。

### 1.3 微信登录

闭包 @`0xbb63b8`，直接命中接口 `app/api/app/v1/login`：

```
参数：code（微信授权码）、sessionId
  ├─ 失败 → "微信登录失败"
  └─ 首次登录 → "首次微信登录，需要先绑定手机号"
               → 跳 bind_wx_suggest_page
```

### 1.4 一键登录（运营商 / 闪验）

平台通道方案，Dart 侧只做发起与回调注册：

```
LoginChannelProxy::openLoginAuth @0xbb2bd8
  → PlatformMethodChannel::openFlutterChannel      // 进原生
  → 构造 MethodChannel
  → MethodChannel.setMethodCallHandler             // 注册接收
  → LoginChannelProxy 实例持有 _channel

回调分支（LoginChannelProxy 内）：
  _onLoginError            @0xbb7a6c   登录失败
  _onClickOtherPhoneLogin  @0xbb7a04   换手机号登录
  _onBack                  @0xbb8434   用户取消
  _onOpen                  @0xbb8498   拉起授权页
```

服务端接口对应 `app/v1/oneClick/login`（闭包 @`0xbb7168`）与荣耀专用 `app/v1/oneClick/login/honor`（闭包 @`0xbd69a8`）。

**闭包 `goSyOneLogin` @`0xbb6700`** 返回 `Future<Map>` —— `sy` 即闪验（Shanyan）SDK，是取号的实际执行者。

### 1.5 Apple 登录与统一收口

```
_LoginPageState::_getLoginAuthCallback @0xbb2224
  → 构造 LoginAuthCallback{ _solveAppleLogin, interfaceAppleLogin }
  → _solveAppleLogin → interfaceAppleLogin → Future.then
  → UserManager::loginSuccess          // ★ 登录态统一收口点
  → _CodeInputContainerState::updateFirstShow
      → _LoginPageState::registerFlashSignCallback   // 注册闪验回调
      → setState
  → MsgUtil.toast（失败时）
```

**结论**：所有登录方式（验证码 / 微信 / 一键 / Apple）最终都汇聚到 `UserManager::loginSuccess` @`0x7e2bfc` 附近，token/sessionId 的落地只在这一处。

### 1.6 登录链路总览

```
[登录页]
  ├─ 手机号+验证码 ：buildBtn → getValidCode → interfaceSendValidCode → 输入框回调(0xbd793c) → 提交
  ├─ 微信          ：WXEntryActivity → 闭包0xbb63b8 → app/api/app/v1/login(code, sessionId)
  ├─ 一键登录      ：openLoginAuth → 原生MethodChannel → oneClick/getMobile → oneClick/login
  ├─ 荣耀一键      ：oneClick/login/honor
  └─ Apple         ：_solveAppleLogin → interfaceAppleLogin
                        ↓ 全部汇聚
                   UserManager::loginSuccess → 写 token/sessionId
```

## 二、门禁开门

### 2.1 总策略：远程优先，蓝牙兜底

```
BlueKeyTools::checkoutBlueOpenDoor @0x83f570
  toast("远程开门失败，正尝试蓝牙开门")     // [pp+0xdf68]
  → BlueKeyTools::blueOpenDoor @0x835504
```

这段字符串直接证明了顺序：**先走远程开门，失败后才启用蓝牙**。`checkoutBlueOpenDoor` 的调用者是 `HomePageState` 闭包 @`0xce6c38` 和 `door_tools.dart::checkShouldScanBle` @`0x7eeae8`。

### 2.2 远程开门响应处理

`HomePageState` 闭包 @`0xce6c38`（9 段代码，第一段 0x128 字节）解析返回体：

```
读 data["code"] → 读 data["data"]
  → data["res"]            // 结果包装
  → data["openDoorState"]  // 开门状态机字段
  → data["doorControlName"] // 门禁点名称
分支：cmp x4, #0x3f (Smi 63) → 特定业务码

```

接口路径：`open/doorcontrol/v2/open`（字符串常量，出现 3 次）。

### 2.3 蓝牙可用性与权限分支

```
BlueKeyTools::blueOpenDoor
  FlutterBlue.isAvailable          // 设备是否支持 BLE
    └─ 否 → 走不可用分支
  FlutterBlue.isOn                 // 蓝牙开关
    └─ 关 → debugPrint("蓝牙是否开启：" + state)
  initCentralManager               // 初始化中心设备管理器
  状态码分派（0x84fd80 段）：
    x0 == 0x14 (20) 或 x0 == 2  → ValueNotifierManager.updateValue("valueBlePermission", …)
    x0 == 0x15 (21)             → BlueKeyTools::hasBluetoothPermission
```

这解释了 Android 12+ 的 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` 运行时权限申请：扫描权限被拒时只更新通知器，不进入扫描。

### 2.4 扫描与设备匹配


`stopScanListener` 内含关键字符串：**"蓝牙开门，本地缓存的sessionId过期强制退出登录"** —— 说明蓝牙开门依赖本地缓存的 sessionId（离线钥匙），过期即强制登出。

## 四、边界说明

1. **间接调用不可见**：Dart AOT 大量通过对象池/分派表调用，`bl` 只能捕获直接调用。闭包作为回调传递时（如 `checkoutBlueOpenDoor` 由 UI 回调触发），调用者索引为空 —— 这是数据缺口，不是没分析。
2. **条件分支是汇编级**：`cmp` + `b.xx` 配合字符串常量能还原判定意图，但复杂布尔组合（多个 `tbz` 串联）需要逐段人工翻译。本文只翻译了字符串能锚定的分支。
3. **原生层仍未覆盖**：一键登录取号、微信 SDK 回调、BLE 栈都在 Java/C++ 侧；Java 侧被 `com.mx.shell` 加密，本次未脱壳。
